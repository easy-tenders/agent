# Операция — завести поставщика

**Когда:** «запиши поставщика: <кто>, <контакт>, <что возит>», «нашла оптовика по
климатике», «этот отработал хорошо / плохо».

**Шаги:**

1. **Проверь дубль** — поиск по названию и телефону в `suppliers/`. Совпадение →
   дополняй, не плоди.
2. **Создай** `suppliers/<название>.md` по форме
   `meta-vault/forms/vault-template.md`: чем торгует, контакты, город, ряд на рынке.
3. **Надёжность — с основанием.** Требование самой владелицы: «проверить, сколько
   лет на рынке». Основания нет → поле остаётся пустым, оценку не выдумываем.
4. **Цены — с датой.** Цена поставщика без даты бесполезна: маржа считается по
   сегодняшней. Розница это или закупка — отмечай прямо.
5. **Сделка прошла** → строка: что брали, по какой цене, как отработал. Сделка не
   состоялась — тоже записываем, отрицательный опыт это данные.
6. **Свяжи с лотом**, под который искали — ссылкой на его карточку в `tenders/lots/`
   (имя файла = номер закупки).
7. Новый сервис поиска, а не поставщик → строка в `suppliers/gde-iskat.md`.

**Крайние случаи:**
- Контакт — только телефон и ряд на рынке → карточка всё равно заводится, это
  нормальная форма контакта в этой нише.
- Поставщик найден на площадке (Kaspi, Satu) → это **не поставщик**, а витрина
  цены; такие цены живут в расчёте лота, карточку заводим только на того, у кого
  реально покупаем.

**Важно:** контакты третьих лиц — персональные данные. Карточка живёт в приватном
репозитории и наружу не уезжает; в отчёты и на публикацию контакты не попадают.
