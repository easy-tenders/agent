# engine — чем агент действует

Код: сбор данных с портала и рендер отчётов. **Правила живут в доменах, знание об
инструментах — в памятках** (`tenders/tenders-vault/tools/goszakup.md`). Здесь только — что чем запускается и в каком
состоянии код.

## Что нужно на машине

Скрипты запускает агент, не человек руками. На чистой машине нужны:

| Что | Зачем | Если нет |
|---|---|---|
| Python 3.8+ | всё | поставить с python.org, при установке отметить «Add to PATH» |
| `reportlab` | только рендер PDF-отчётов | `pip install reportlab` |
| `pdftotext` или `pypdf` | чтение протоколов закупок | `pip install pypdf` — проще всего |

Больше ничего. Сбор данных с портала идёт стандартной библиотекой: внешний `curl`
не нужен, ЭЦП не нужен, всё берётся с публичной части портала. Шрифты отчётов лежат
в репозитории (`report/fonts/`), ставить их в систему не надо.

Скрипт, которому чего-то не хватает, останавливается и пишет, что именно поставить.

## Скрипты

| Файл | Что делает | Дёргается операцией |
|---|---|---|
| `common.py` | общее: запросы к порталу с паузой, временные папки, чтение PDF и HTML | — библиотека |
| `scripts/collect_open.py` | собирает все открытые лоты по ключевому слову с деталями (сайт портала, HTML) | [[naiti-loty]] |
| `scripts/ows.py` | API портала по токену: лоты по слову за секунды, лот подробно, документы лота в папку (`docs`), кто выигрывал (договоры), годовые планы заказчиков, участник по БИН, справочники; `check` — есть ли доступ | [[naiti-loty]] · [[sobrat-otchet]] · памятка `tenders/tenders-vault/tools/ows-api.md` |
| `scripts/niche.py` | статистика прошлых закупок по товару: участники, скидки, победители | [[sobrat-otchet]] |
| `scripts/winprice2.py` | скидка победителя от плановой суммы; колонки определяет по заголовку таблицы | [[sobrat-otchet]] |
| `scripts/rating.py` | рейтинг открытых лотов по ожидаемой марже | [[otsenit-lot]] |
| `scripts/extract_docs.py` | вытаскивает текст из docx/xlsx/pdf/xls | разбор материалов владельца |
| `report/maksi_style.py` | рендерер PDF: палитра, шрифты, сетка | — библиотека |
| `report/report_obzor.py` | отчёт 1 — обзор рынка ниши | [[sobrat-otchet]] |
| `report/report_detail.py` | отчёт 2 — детальный разбор лотов | [[sobrat-otchet]] |
| `data/ceny-rynka-*.json` | снимок рыночных цен: одна ниша, один день | — данные |

Запуск — из папки `engine/`:

```
python scripts/collect_open.py "кондиционер"
python scripts/rating.py ceny-rynka-kondicionery-2026-07-25.json
python scripts/niche.py "кондиционер"
python scripts/winprice2.py "кондиционер"
python scripts/extract_docs.py <папка с материалами>
```

Промежуточные данные скрипты кладут во временную папку системы (её путь печатается
в конце), а не в базу. В базу попадает только то, что записано операцией.

**Файл цен указывается явно и обязателен.** Это снимок рынка на один день по одной
нише; для новой ниши делается новый файл с новой датой в имени. Значения по умолчанию
нет нарочно — иначе легко посчитать новую нишу по ценам старого прогона и не заметить.

## Состояние кода — читать до запуска

Прогон 25.07 делался «по горячему», пути остались зашитыми. **Прежняя запись «два
скрипта из восьми не запустятся на чистой машине» была неправдой:** она мерила
машину исполнителя, где стояло всё нужное. На чистой машине не запускался **ни
один** из восьми.

**Починено 2026-08-02** (проверено живым прогоном по нише «кондиционеры»):

- пути машины исполнителя убраны отовсюду — временные папки берутся у системы,
  папка с материалами и файл цен передаются аргументом;
- запросы к порталу — стандартной библиотекой вместо внешнего `curl`;
- чтение протоколов не привязано к `pdftotext` по абсолютному пути: инструмент
  ищется в системе, есть запасной вариант на `pypdf`;
- шрифты отчётов вложены в репозиторий (`report/fonts/`, лицензия SIL OFL
  разрешает распространение) — раньше брались из `~/Library/Fonts`;
- цены и модели кондиционеров вынесены из кода в `data/ceny-rynka-*.json`;
- **закупки из одного источника перестали теряться молча.** Портал отдаёт их
  HTML-ом вместо протокола об итогах; раньше такой файл скармливался в `pdftotext`,
  разбор проваливался и лот исчезал из статистики без следа. Теперь формат
  определяется по содержимому, а пропуск считается и печатается строкой. На нише
  «кондиционеры» это 4–8 закупок из каждой выборки — те самые «из одного источника»,
  которые владелец и велела не смотреть.

**Починено 2026-10-22** (поиск отдавал ноль с осени — proverka-poiska-2026-10-21;
проверено живым прогоном 22.10):

- адрес портала — одна строка `PORTAL` в `common.py` (`old.goszakup.gov.kz`, запасной —
  зеркало `procurement.gov.kz`); ссылки на лоты ловятся по пути, хост любой;
- открытые лоты — статусы 210 + 220 + 240, все страницы выдачи; лоты с прошедшим сроком

**Добавлено 2026-10-23 — `scripts/ows.py`, API по токену.** Собран по схеме
GraphQL v3 портала; `selftest` проходит без сети. **Живой прогон 23.10 с машины

**Что остаётся долгом:**

- **Два отчёта — не рендереры, а исходники двух конкретных PDF от 25.07.** Текст

## Правила

- **Капчу не обходим.** Стоит защита — страницу открывает человек, агент читает.
- **Ничего не подаём и не отправляем.** Агент только читает; всё наружу — через
  шаг `⏸ operator`.
- **Доступы — в `secrets/`**, никогда в коде.
- Между запросами к порталу — пауза (держится в `common.py`, отдельно в скриптах
  не нужна).
- **В коде не должно быть путей чужой машины.** Нашли такой — это дефект, строкой
  в состояние базы.
- **Данные прогона — не в код.** Цены, модели, номера лотов, выводы конкретного
  разбора живут в `data/` с датой в имени. Число в коде — тот же дефект, что и путь.
