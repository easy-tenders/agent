# Завести движок

**Движок** — код, которым агент действует: скрипты, импортёры, сборка отчётов,
поиск по порталу, монтаж, запись и расшифровка. Знание о движке — в vault,
сам код — в `engine/` рядом.

**Когда:** «нужен скрипт / автоматизация / чтобы агент сам собирал …», шаг 0
[[build-namespace|сборки]] показал ручную работу, которую делает код, а не
разговор.

**Сначала проверь, что это движок.** Агент с операцией справляется сам —
кода не надо. Код нужен, когда шаг повторяется одинаково, данных много или
нужна внешняя программа (ffmpeg, браузер, PDF). Сомнение → ⏸ владелец.

## Шаги

1. **Где живёт.** Код зовут операции одного домена — `<домен>/engine/`;
   операции двух и больше доменов — `engine/` в корне. Описание — по [[../forms/engine-form|форме]]:
   `<домен>-vault/engine.md` или `meta-vault/engine.md`.
2. **Зависимости — одним файлом:** `engine/requirements.txt` или
   `engine/pyproject.toml` (Python). Другой язык — строка в описании и шаг в
   `engine/setup-extra.sh` / `engine/setup-extra.ps1`.
3. **Системные программы** (ffmpeg, шрифты, браузер) — в
   `engine/setup-extra.sh` (macOS: `brew install …`) и
   `engine/setup-extra.ps1` (Windows: `winget install … --scope user`).
   `bin/setup` и `bin/setup.ps1` зовут их сами.
4. **Платформы — честно.** Для каждого исполнителя: работает на macOS ·
   Windows · Linux. Не работает на машине владельца — так и написать в
   описании и в двери («монтаж пока только на Mac»). Пути — только
   относительные от корня или через `os.path.join` / `pathlib`; временные
   файлы — `tempfile`, не `/tmp`. Кодировка файлов — `utf-8` явно.
5. **Данные и модели движка** (кэш, веса, выгрузки) — вне git: строка в
   `.gitignore`, в описании — где лежат и как получить заново.
6. **Ключи** — только `.env` / `secrets/`, имена ключей — строкой в
   `secrets-map.md`. В `.mcp.json` — только `${ИМЯ_КЛЮЧА}`, не значение.
7. **Исполнители** — строка на каждый скрипт в `../../inventory/executors.md`;
   операция, которая его зовёт, называет его в поле `исполнитель:`.
8. **Установка — с согласия владельца:** `bin/setup` ставит недостающие
   программы (Python, ffmpeg) на его машину — сказать, что поставится, и
   ждать слова.
9. **Тест на чистой машине:** `sh bin/setup` (macOS) /
   `powershell -ExecutionPolicy Bypass -File bin\setup.ps1` (Windows) с нуля,
   затем одна живая операция. Не прогнано на платформе владельца — статус
   операции `possible`, и это строка в «Что есть и чего нет».
10. Дверь: в «Первый запуск» — «нет `.venv` → `bin/setup`»; в «Что есть и чего
   нет» — платформы. `python3 bin/check` — чисто. Checkpoint-коммит.

**Не здесь:** RAG и поиск по базе — не движок по умолчанию: база читается
агентом напрямую, индекс заводится, когда без него не отвечают.
