# Форма передачи

Корневая дверь `CLAUDE.md` живёт с первого дня сборки. Когда неймспейс
передаётся человеку, который будет открывать его сам, дверь доводится этими
разделами. Человек открывает репозиторий без нас — дверь должна выдержать это.

## Разделы, которые добавляются

Сначала выбирается **способ доставки** — от него зависит «Как начать»:

| Способ | Когда | «Как начать» |
|---|---|---|
| **GitHub** (приватный репозиторий) | владелец будет работать с нескольких машин или мы обновляем базу | clone по SSH, раздел «Доступ» ниже |
| **Машина владельца** | сборка идёт прямо на его компьютере, в его Claude | папка уже на месте: открыть корень |
| **Архив / флешка** | нет GitHub, машина одна | `git bundle create база.bundle --all` → у владельца `git clone база.bundle <папка>`; история едет вместе |

~~~
## Как начать (дословно)

1. <по способу доставки: `git clone git@github.com:<аккаунт>/<репозиторий>.git` ·
   папка уже на месте · `git clone база.bundle <папка>`>
2. Чистая машина — подготовить её одной командой из корня:
   macOS — `sh bin/setup` · Windows —
   `powershell -ExecutionPolicy Bypass -File bin\setup.ps1`.
3. Открыть корень в Claude — дальше ведёт эта дверь.
4. Первый запрос: «<живой вопрос владельца, на который база точно отвечает>».

## Доступ к репозиторию — один раз на устройство

Репозиторий приватный, машине нужен доступ — **SSH-ключ**, заводится на
своей машине:

    ssh-keygen -t ed25519 -C "<имя устройства>" -f ~/.ssh/id_ed25519

Открыть `~/.ssh/id_ed25519.pub`, скопировать строку целиком, вставить на
`github.com/settings/keys` → **New SSH key**. Проверка: `ssh -T git@github.com`
отвечает приветствием с логином. Файл без `.pub` остаётся на машине навсегда
и никуда не пересылается. Порт 22 закрыт → в `~/.ssh/config`:
`Host github.com` / `HostName ssh.github.com` / `Port 443`.

## Шаг 0 — секреты

Ключи в git не хранятся. `secrets/` создаётся руками на каждой машине; что в
неё положить — `meta-vault/secrets-map.md`. Значения передаются только вне git.

## Windows  <обязателен, если машина владельца — Windows>

- Папку класть поближе к корню диска (`C:\<имя>\`), не глубоко в
  `Документы`: Windows не создаёт файлы с путём длиннее 260 символов.
  `bin/check` предупреждает о путях длиннее 200.
- Длинные пути включает владелец машины, один раз, PowerShell от
  администратора:
  `New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force`
- Python зовётся `py`, а не `python3`: `py bin\check`.
- <что из движка на Windows не работает — честно>.

## Правила

- **Разделы выпадают по способу доставки.** «Доступ к репозиторию» — только
  для GitHub; «Windows» — только для машины на Windows; «Точность данных» —
  только для снятых данных. Условный раздел, оставшийся в двери с
  `<обязателен, если…>`, — недоделка: перед передачей их ноль.
- **Доступ — SSH-ключом, не браузерным входом.** `gh auth login` через
  браузер на чужих машинах падает устойчиво (истекает код, не тот браузер,
  корпоративный SSO). Deploy key не предлагать — он на один репозиторий.
- **Приватную половину ключа не пересылают никогда.** Генерирует владелец у
  себя; ему дают текст команды, не ключ.
- «Что есть и чего нет» обязателен: без него человек верит, что база умеет
  всё, и первый же провал читает как поломку.
- Старый источник закрыт → сказать прямо здесь.
- **Дверь не врёт о доставке.** Сменилась видимость репозитория, remote или
  способ доставки — дверь правится в том же коммите. Иначе через месяц она
  пишет «репозиторий публичный», а он давно закрыт.
- Публичный репозиторий — только для шаблона без данных владельца. База с
  именем, перепиской или выгрузкой владельца — приватная или без remote.
