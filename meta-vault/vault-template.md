# Vault template — папка как точка входа + vault + записи рядом

**База-баз** того, как устроен уровень: папка, её vault и папки записей рядом
с vault. Домены соответствуют этой форме и записывают только свои **дельты**
в собственной `principles.md`. Правила письма — [[principles]]; этот файл —
**структура + контракт точек входа**. Изменение этого файла меняет всё, что
от него родится, — поэтому каждое изменение формы получает строку в §Журнал
формы.

## Модель — точка входа это папка

Папка уровня — **не** только её vault. В ней vault (знание + метод) **плюс**
папки записей рядом **плюс** код-проекты, файлы — что угодно. Открыв папку
как cwd, агент с первой попытки должен понять, что это за место, найти vault,
каждую папку записей и каждый проект.

```
<домен>/                     ← ТОЧКА ВХОДА (папка, открываемая как cwd)
  CLAUDE.md        [door]     ← авто-грузится харнессом. Манифест.
  <домен>-vault/              ← ЗНАНИЕ + МЕТОД (как делаем, что знаем)
    HOME.md        [map]      ← семантическая навигация
    status.md      [hot]      ← состояние сейчас (+ §Структура)
    principles.md  [rules]    ← «следует базе + эти дельты»
    questions-ВЛАДЕЛЕЦ.md     ← что ждёт слова владельца, вопрос строкой
    operations.md + operations/ ← что здесь делается — по операции, не по памяти
    planning.md docs.md …     ← ОПИСАНИЕ каждой папки записей (файл рядом с её именем)
    decisions/ systems/ …     ← тело (ниже)
  planning/ ledger/ …         ← ЗАПИСИ, папка на род; реестр внутри = registry.md
  docs/ inbox/                ← файлы, вне git
  <проект>/ CLAUDE.md         ← у каждого код-репо своя дверь
```

## Шов — vault = знание и метод; записи рядом

Vault держит **как мы делаем и что мы знаем**; **что мы сделали и что у нас
есть** живёт в папках записей рядом с vault, одна папка на род. Тест перед
каждой записью:

> *«это как мы делаем / что мы знаем — или что мы сделали / что у нас есть?»*

Знание → vault: метод, форма, принцип, описание папки записей, карточка
системы, решение, урок. Запись → папка рядом: строка реестра, состояние,
журнал, экземпляр плана, прогон, карточка человека или клиента.

**В vault есть файл с именем каждой папки записей** — её описание и метод
(`planning.md` говорит, что такое наш план и как он ведётся). Сама папка
держит записи и **никаких правил**.

## Контракт точек входа

**Цепочка: дверь → `HOME.md` → знание.** Одна роль на файл.

- **Дверь.** Харнесс авто-грузит её от cwd вверх по родителям; больше ничего
  не авто-грузится. Имя зависит от инструмента: **`CLAUDE.md`** (Claude Code),
  **`AGENTS.md`** (Codex и другие); папка под двумя инструментами несёт оба
  файла как синхронные твины. Обязательна в каждом открываемом cwd. Дверь —
  **манифест**: (а) что это за место, (б) маршрут в vault (`HOME.md` +
  `status.md`), (в) **перечисление папок записей, проектов и зон**,
  (г) реестр операций уровня. Тонкая и стабильная. Агент один на всё
  пространство — **дверь не задаёт личность**, она карта комнаты.
- **`HOME.md` — карта.** Через дверь, никогда не авто-грузится. Ровно одна
  на корень vault. **По разделу на каждую папку записей** (что · где ·
  файл-описание · операции).
- **README в наших зонах нет.** Харнесс открывает только дверь, остальное
  достигается ссылкой — значит, файл назван по роли ([[principles]] §Имя
  файла = его роль). README остаётся только в коде, который читают снаружи.
  Маршрутизация, лежащая только в README, для агента не существует.

## Форма vault

**Обязательный хребет**

- `HOME.md` · `status.md` (+ §Структура) · `principles.md` ·
  `secrets-map.md` (пусть даже «секретов на уровне нет»).
- `questions-ВЛАДЕЛЕЦ.md` — **единственный файл того, что ждёт слова
  владельца**: вопрос строкой, указатель на источник, новое сверху. Вопросы —
  не задачи (те — в план) и не решения (те получают датированный файл после
  ответа). Агент спрашивает по одному, когда вопрос встал в работе; весь
  список — по просьбе. `ВЛАДЕЛЕЦ` в имени заменяется именем владельца
  заглавными, без угловых скобок (их запрещает NTFS).
- `operations.md` + `operations/` — реестр и файлы операций (§Операции).
- `tasks.md` — **форма** цикла крупной задачи (`spec → plan → build → review
  → record`); данные прогонов — записи, живут рядом с vault.

**Общее тело** (каждая зона рождается с первым объектом)

- `decisions/` — датированные прецеденты, слово владельца дословно;
  описание — `decisions.md`.
- `systems/` — свои компоненты (что и зачем, не имплементация).
- `lessons/` — операционные правила (триггер → правило → почему).
- `tools/` — карточки внешних инструментов (как пользоваться, ограничения;
  ключи — только указатель в `secrets-map`).
- `_archive/` — терминальная; из карт ссылок нет, из решений — можно.

**По типу дела**: `market.md` (рынок и метод маркетинга, записи — рядом) ·
`clients.md` (форма карточки клиента, папки клиентов — рядом) · `research/`
(разборы с TL;DR) · `analytics/` (каждая заметка: окно данных · источники ·
метод · цифры — вывод воспроизводим, а не принимается на веру).

## Папка записей — форма

- **Рождается с первым объектом**, не на вырост.
- **Тест на новую папку — оба условия:** своя единица хранения (не сводится
  к соседней) **и** свой ритм роста. Одно не выполнено → подпапка внутри
  существующей.
- **Внутри — только записи.** Описание — `<vault>/<папка>.md`; реестр строк —
  `registry.md`; форма файлов подполки — `form.md`.
- **Файл-описание** держит: что где (таблица путь → что) · правила, включая
  границу (что сюда никогда не кладётся) · как растёт (новый объект / месяц /
  год) · чего нет — честный список дыр.
- **Копящееся во времени — по годам/месяцам с первого дня**, год — как его
  считает дело (календарный, учебный, финансовый).
- **В записях нет задач, решений и истории:** задачи → `planning/backlog.md`;
  решения → `decisions/`; история → git.
- **Рождается с тремя строками:** раздел в `HOME.md`, абзац в двери и хотя бы
  одна операция, которая её читает или пишет.

## Операции

Агент действует **по операции, не по памяти**.

- **Два рода, нужны оба:** *write* (записать, изменить, принять, закрыть) и
  *read* (ответить на вопрос, который владелец задаёт регулярно). Уровень с
  одними write — вверх ногами: владелец спрашивает чаще, чем диктует.
- **Шапка:** `вызов: фраза | скилл | событие` · `исполнитель: агент | скилл →
  <имя> | код → <путь>` · `статус: possible | in-dev | live` (live — только
  после живого прогона).
- **Скилл — атомарный исполнитель; операция — действие уровня.** Операция
  знает свои скиллы; скилл свои операции не перечисляет. Правда действия
  живёт в операции.
- **«Когда»** — живые фразы владельца, его словами. **Шаги называют
  конкретные файлы**, которые меняют, — так vault и папки записей
  синхронизируются.
- **`⏸ владелец`** на каждом шаге, где решает человек; всё, что уходит из
  базы наружу, проходит такой шаг.
- **Read-операция говорит, где база врёт:** пустая ячейка не ноль, нет
  отметки — не долг.
- **Новая операция → три строки:** в `operations.md` уровня, в двери, в
  `HOME.md`.
- **Готовность уровня:** вопросы, на которые он отвечает («как идут дела»,
  «что построено», «что решили»), — read-операции; уровень готов, когда
  дверь + `HOME.md` + `status.md` на них отвечают.

## Контракт status.md

`status.md` — **горячее состояние**, читается каждую сессию. **Блокеры видны
верхнему агенту без закапывания в боковые доки.**

- **Blockers / «не сделано» — первыми.** Что не сделано и чем гейтится.
  Реальный блокер в `docs/*.md` невидим тому, кто читает дверь + status.
- **«Работает» ≠ готово.** Всегда парой: что работает + что блокировано.
- **Блокеры, гейтящие верх, поднимаются вверх** — конкретной строкой в
  `planning/backlog.md` верха.
- **Снимок, не журнал.** Как сейчас; история — git; хвосты — в план. Больше
  ~60 строк — стал журналом, режь.
- **§Структура — состояние сборки уровня, отдельно от состояния дела:**
  цифры здоровья с датой (битые ссылки, секреты в индексе git — из прогона,
  не на глаз; ноль без даты — не запись) · последние изменения устройства ·
  таблица расхождений с базой (*правило базы · как здесь · почему*).

## База + дельты

`principles.md` домена открывается словами *«следует базе + эти дельты»* и
перечисляет только отличия. Новые домены рождаются из этого шаблона.

- **Расхождение либо исправлено, либо записано — третьего нет.** Молчаливое
  расхождение рождает две несовместимые редакции правила.
- **Сверять три вещи:** форму в базе · дельты уровня · **как реально написаны
  файлы** — решает третье.
- **Изменённая форма датируется; старое массово не переписывается.**

## Журнал формы

Новое сверху. Строка — только про то, что меняет форму или правило.

- **2026-10-22** — **один шаблон для всех**: личный неймспейс, база клиента,
  агент с кодом — одна форма (слово владельца линии 22.10 «да, единый
  шаблон»). Добавлен **слой поставки**: операция `operations/add-engine`
  и форма `forms/engine-form` (движок = код, которым агент действует;
  описание `engine.md` в vault, платформы колонкой); `bin/setup` (macOS,
  Linux) и `bin/setup.ps1` (Windows, UTF-8 с BOM) — чистая машина одной
  командой, хуки `engine/setup-extra.*`; `.gitattributes` (LF, CRLF у
  `.ps1`/`.cmd`); `bin/check` ловит имена, запрещённые Windows, и
  предупреждает о путях длиннее 200 символов и путях чужой машины. Форма
  передачи: способ доставки (GitHub · машина владельца · `git bundle`),
  раздел Windows, «дверь не врёт о доставке». `structure.md`: разделы
  «Что просили, а мы не построили» и «Уроки для шаблона» — отсюда уроки
  поднимаются в шаблон. Приём версии — и из папки, без сети. Термин
  **engine** расширен: код агента, RAG — частный случай. `README.md` и
  `LICENSE.md` — только у публичного зеркала шаблона, в сборку не едут.
- **2026-10-10** — пересборка под текущую форму + **конструктор внутри**:
  агент в свежем клоне собирает неймспейс владельца по рецепту
  (`operations/build-namespace` · `new-domain` · `check-links-and-names` ·
  `accept-new-version`), формы в `forms/`, пример в `examples/`, прогон —
  `bin/check`, состояние сборки — `structure.md`. Ссылки на повторяющиеся
  имена — путём.
  **записи вынесены из vault** (`backlog` → `planning/`, автоматизации →
  `inventory/`, ledger офиса → `office/ledger/`); **README убраны из зон** —
  описание зоны `<имя>.md` рядом с папкой, контракт `secrets/` переехал в
  `secrets-map.md`, `README.md` остался только в корне для GitHub;
  **один агент на всё пространство** + `inventory/executors.md`; в хребет
  домена добавлены `questions-ВЛАДЕЛЕЦ.md`, `operations.md` + `operations/`,
  `status.md` §Структура; **сток `archive/` + `INDEX.md`** — ничего не
  удаляется; в инвариант — «сделай» vs «мысль вслух» и «наружу — только по
  слову»; закрытие сессии с checkpoint-коммитом.
- **2026-07-30** — форма неймспейса: тонкая мета, домены `project/` и `office/`.
