# Операция — завести карточку лота

**Когда:** «запиши этот лот», «сохрани закупку <номер>», «положи в базу, потом
вернёмся», «мы подали на этот лот».

Без этой операции работа агента исчезает: расчёт сделан, отчёт показан — и назавтра
в базе пусто. Всё, что разобрано, кладётся сюда.

**Шаги:**

1. **Проверь дубль** — поиск по номеру закупки в `tenders/lots/`. Есть карточка →
   дополняй её, не заводи вторую.
2. **Создай** `tenders/lots/<год>/<номер-закупки>.md` по форме
   `meta-vault/forms/vault-template.md`. Год — календарный, как считает портал.
3. **Впиши снятое с портала:** заказчик, способ закупки, код ТРУ, характеристика,
   цена за единицу, количество, сроки приёма и поставки. **Каждое поле — с датой
   снятия.** Данные с портала и оценки агента — разными строками.
4. **Впиши требования из документации**, если она разобрана: спецификация, проект
   договора, обеспечения. Не разобрана — так и пометь, не оставляй поле пустым молча.
5. **Приложи расчёт**, если он делался: цена подачи, затраты, маржа в двух режимах,
   точка безубыточности, вердикт. Формулы не пересказывай — они в [[schitat-marzhu]].
6. **Свяжи:** поставщик, у которого считали товар → ссылка на его карточку в
   `suppliers/`; правило, по которому шёл отбор → карточка в `method/`.
7. **Подала заявку** → строкой: с чем шли, по какой цене, когда. **Опубликованы
   итоги** → кто выиграл и с какой ценой; это превращает карточку в материал для
   аналитики будущих лотов.

**Крайние случаи:**
- Номера закупки нет (нашли по объявлению) → заводи по номеру объявления и пометь,
  что номер лота уточняется. Имя файла потом не переименовывается — ссылки поедут.
- Владелец диктует по памяти, портала под рукой нет → пиши как её слова, пометь
  «со слов, не сверено», сверку — отдельным заходом.

**Важно:** пустое поле не значит «ноль» или «не требуется». Не заполнено —
значит не смотрели, и так и должно читаться.
